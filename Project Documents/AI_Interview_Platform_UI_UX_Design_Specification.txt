1. Design Goal
The application should feel like a professional SaaS product. The UI must emphasize clarity, hierarchy, useful
information and strong primary actions rather than decorative complexity.
2. Design Principles
Principle
Requirement
Clean
Use whitespace, clear hierarchy and minimal visual noise.
Modern
Use contemporary SaaS patterns such as cards, tabs, progress indicators and
responsive dashboards.
Professional
Keep typography, spacing, components and visual language consistent.
Minimal
Show the most important information first; use progressive disclosure for secondary
details.
Fast
Avoid unnecessary effects and provide clear loading/processing feedback.
Responsive
Layouts adapt across desktop, tablet and mobile.
Accessible
Use readable contrast, keyboard access, focus states and clear form labels.

7. AI Interview UX
The interview screen should be focused and distraction-free. The current question should be visually dominant
and answer controls easy to access.
Element / State
UX Requirement
Configuration
Choose interview type, difficulty, role and duration.
Question
Show one clear question with context/progress.
Answer Input
Clean text input; voice controls can be added later.
Processing
Show AI-processing state and prevent duplicate submission.
Feedback
Show score, strengths, weaknesses and improvements.
Next Question
Obvious action after evaluation.
Completion
Final summary with links to progress and roadmap.

Area

12. Required UI States
State
Expected Behavior
Loading
Skeleton/spinner or processing indicator while preserving layout where possible.
Empty
Explain that no data exists yet and provide a useful next action.
Error
Human-readable explanation plus retry/recovery where possible.
Success
Confirm the action and show resulting state.
Disabled
Explain why the control is disabled when the reason is not obvious.
13. Responsive Design
Device
Requirement
Desktop

Tablet

Dashboard, resume, progress and roadmap remain usable; coding can be optimized
separately.
14. Accessibility
• Use semantic HTML controls.
• Provide labels for form fields.
• Maintain readable contrast.
• Show visible keyboard focus.
• Ensure controls are usable without a mouse.
• Do not use color alone for success/error communication.
• Show clear error text near the relevant control.
• Provide supporting text/values for chart-based insights.

15. Visual Quality Rules
Rule
Requirement
Consistency
Same component looks and behaves consistently across pages.
Spacing
Use a consistent spacing scale.
Typography
Use a limited hierarchy of sizes and weights.
Color
Use a restrained professional palette; reserve stronger accents for actions/status.
Motion
Use subtle transitions only when useful.
Content Density
Avoid overcrowding; prioritize next action.
Feedback
Async actions visibly transition through relevant states.
Error Recovery
Users should not reach a dead end after an error.
16. Page-Level UX Checklist
Every feature/page should verify:
• Responsive behavior at supported viewport sizes.
• Loading, empty, error, success and disabled states.
• Clear primary action.
• Understandable validation and feedback.
• Reuse of shared components.
• Graceful API failure handling.
• Accessibility basics.
17. Design Outcome
The final application should feel like a polished SaaS product with clear navigation, reusable components,
focused interview/coding experiences, informative analytics and strong feedback states. The UI should
communicate the central value: know your readiness, understand your weaknesses, and know what to do
next.
Implementation rule: UI/UX should support the supplied product requirements. Do not add new mandatory user flows without updating
the PRD.
