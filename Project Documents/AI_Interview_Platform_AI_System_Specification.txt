4. Interview Evaluation
Interview answers should be evaluated using a consistent rubric so results are structured and comparable.
Dimension
Evaluation Meaning
Correctness
Technical accuracy of the answer.
Relevance
How directly the answer addresses the question.
Technical Depth
Depth, reasoning and trade-offs demonstrated.
Communication
Clarity and effectiveness of explanation.
Structure
Logical organization of the answer.
Confidence
Confidence-related signal where supported by the available input.
Completeness
Coverage of important parts of the question.
Structured JSON output:
{ "score": 8, "correctness": 8, "communication": 7, "technicalDepth": 8, "strengths": [], "weaknesses":
[], "improvements": [] }
The JSON response must be validated server-side before storage or display.
Evaluation flow:
Question + Candidate Answer + Rubric → LLM → JSON Response → Schema Validation → Store → Feedback
UI

5. Personalization
Recommendations should use the candidate's history and target context rather than only the current answer.
Input
Personalization Use
Previous scores
Identify trends and repeated weaknesses.
Weak topics
Prioritize topics with low performance.
Question history
Track repeated attempts and unresolved concepts.
Coding history
Use coding performance as skill evidence.
Resume skills
Connect recommendations to claimed and demonstrated skills.
Target job role
Prioritize role-relevant skills.
Difficulty level
Adjust practice/interview difficulty.
Example logic:
Candidate evidence → weak topic → target-role relevance → previous attempts → select next difficulty →
recommend action → re-assess
The system should consider both what the candidate has done and what the target role requires.

7. Reliability and Security Rules
• AI API keys never enter frontend code.
• Treat model output as untrusted until validated.
• Use structured response schemas.
• Show loading, timeout and failure states for AI calls.
• Do not fabricate candidate evidence.
• Store provider/model metadata for important evaluations.
• Keep AI logic behind backend services.
• Use deterministic evaluation for objective tasks whenever possible.
8. End-to-End AI Flow
Candidate Input → Backend Context Builder → AI Task Selection → Provider Adapter → LLM → Response
Validation → Normalization → Persistence → Dashboard/Feedback → Recommendation Update
This document defines the supplied AI-system requirements at the product/system level. Exact prompts,
provider SDKs and final schemas can be refined during implementation without changing the core
responsibilities or constraints.
