1. API Design Principles
The API should be the controlled interface between the React frontend and backend services. The browser should
never call AI providers or privileged database operations directly.
• Use predictable REST resource naming.
• Authenticate protected endpoints.
• Check resource ownership server-side.
• Validate request body, query parameters and route parameters.
• Return consistent success/error structures.
• Never expose secrets such as AI keys, password hashes or internal credentials.
• Keep long-running AI and code-execution operations protected with timeouts and clear processing states.
2. Suggested Base Response Pattern
Success { "success": true, "data": { ... }, "message": "..." } Error { "success": false, "error": { "code":
"VALIDATION_ERROR", "message": "Human-readable message" } }
Exact response fields can be refined during implementation, but frontend and backend should agree on one
consistent pattern.

12. Validation & Error Handling
Scenario
Expected API Behavior
Invalid JSON/body
Return validation error with safe message.
Missing required field
Return 400-level validation response.
Unauthenticated request
Return 401-style response.
Authenticated but forbidden
Return 403-style response.
Resource not found
Return 404-style response.
AI provider timeout
Return controlled error/processing state; do not fabricate result.
Code execution failure
Return compilation/runtime/timeout status without crashing the API.
Unexpected server error
Return generic message and log internal details safely.
13. Pagination / Filtering / Sorting
Collection/list endpoints such as questions, problems, interviews and submissions should support pagination once the
dataset grows.
Suggested query pattern:
GET /api/questions?page=1&limit;=20&topic;=Trees&difficulty;=Medium&search;=binary
Suggested server responsibilities:
• Validate pagination bounds.
• Apply indexed filters where possible.
• Return only fields necessary for the screen.
• Include pagination metadata such as page, limit and total where practical.

14. AI API Data Contracts
AI endpoints should use explicit request objects rather than sending arbitrary frontend data to the model.
Example evaluation request:
{ "interviewId": "...", "questionId": "...", "question": "...", "answer": "...", "rubricVersion": "v1" }
Example evaluation response:
{ "score": 8, "correctness": 8, "communication": 7, "technicalDepth": 8, "strengths": [], "weaknesses": [],
"improvements": [] }
The backend should validate the response schema before saving evaluation data.

16. API Security Rules
• Never expose AI provider keys through API responses.
• Validate and authorize every protected route.
• Perform resource ownership checks for user-scoped IDs.
• Limit upload size and file types.
• Rate-limit authentication, AI and code-execution endpoints.
• Do not return passwordHash, internal tokens or secret configuration.
• Sanitize/log errors without leaking internal stack traces to clients.

17. API Versioning & Compatibility
The supplied API uses the /api prefix. If future breaking changes become necessary, a version such as /api/v2 can be
introduced rather than silently changing response structures used by the frontend.
18. End-to-End API Flow Examples
Candidate interview: POST /api/interviews → POST /api/interviews/:id/answer (repeated) → POST
/api/interviews/:id/finish → GET /api/interviews/:id.
Resume analysis: POST /api/resumes/upload → POST /api/ai/resume-analysis → GET /api/resumes/:id.
Coding: GET /api/problems/:id → POST /api/submissions → GET /api/submissions/:id.
Progress: GET /api/progress → GET /api/progress/analytics.
19. API Definition of Done
• Endpoint implemented and routed.
• Authentication/authorization applied where required.
• Input validation implemented.
• Database interaction follows the approved schema.
• Success and error responses are documented.
• Tests cover the critical behavior.
• Frontend integration works with the documented contract.
• Sensitive data is not exposed.
20. Final API Blueprint
Authentication → Users → Resumes → AI → Interviews → Questions → Coding → Progress
The API layer should remain a stable contract between UI and backend services. Detailed schemas, model definitions
and AI response formats should evolve through intentional versioned changes rather than ad-hoc endpoint additions.
