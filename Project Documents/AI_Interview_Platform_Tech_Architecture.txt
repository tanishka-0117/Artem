1. Technology Architecture
The stack is designed around a TypeScript-based MERN-style web application with a React frontend,
Node/Express backend, MongoDB database and a separate AI/code-execution integration layer.
High-level flow:
React/Vite Frontend ↓ Node.js + Express API ↓ MongoDB Atlas ■ ↓ ■ AI APIs Storage Email ↓ Docker Code
Execution

5. Authentication & Security Stack
Technology
Purpose
JWT
Authenticated access/session mechanism.
HTTP-only cookies
Protect authentication tokens from direct JavaScript access.
bcrypt / Argon2
Secure password hashing.
Security implementation requirements:
• Keep secrets and credentials in backend environment configuration.
• Never expose AI API keys in the frontend.
• Validate protected routes and check resource ownership server-side.
• Use secure file upload rules.
• Apply rate limiting and appropriate HTTP security headers.
• Run user-submitted code in an isolated environment.
6. AI Stack
Possible providers are OpenAI, Groq and Gemini. The provider layer should remain configurable so the
application is not tightly coupled to one vendor.
AI tasks include:
• Resume analysis
• Question generation
• Adaptive interview follow-ups
• Answer evaluation
• Feedback generation
• Personalized recommendations
• Coding hints and explanations
• Learning roadmap assistance
Recommended backend AI abstraction:
AIService ↓ ProviderAdapter ■■ OpenAI ■■ Groq ■■ Gemini ↓ Response Validation ↓ Business Logic ↓
MongoDB / Frontend

8. Code Execution
The coding feature requires an isolated execution service. Docker-based execution is the proposed approach.
Code flow:
User Code → Backend → Isolated Container → Compile → Test Cases → Execution Metrics → Result →
Submission History
The executor should enforce CPU, memory, execution-time, process and output limits. It should not have
unrestricted access to application secrets or the host system.
9. Email
Nodemailer is the proposed email integration for functions such as email verification, password-reset links and
system notifications.

12. Environment Configuration
Sensitive credentials must be supplied through environment variables/secrets.
Example backend environment names: MONGODB_URI=... JWT_SECRET=... AI_PROVIDER=... OPENAI_API_KEY=...
GROQ_API_KEY=... GEMINI_API_KEY=... CLOUDINARY_CLOUD_NAME=... CLOUDINARY_API_KEY=...
CLOUDINARY_API_SECRET=... EMAIL_HOST=... EMAIL_USER=... EMAIL_PASSWORD=... CODE_EXECUTOR_URL=...
FRONTEND_URL=...
Never commit real values to GitHub. Provide an .env.example containing placeholder names only.
13. Recommended Engineering Principle
Keep integrations modular. The frontend should talk to the application backend; the backend should own
provider credentials and coordinate AI, storage, email and code execution. This makes the application easier
to test, secure, replace or scale later.
